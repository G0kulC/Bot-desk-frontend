# Bot Desk – admin UI

React 18 + Vite + TypeScript (strict) admin app for Bot Desk. Works on a 390px phone and a laptop, in light
and dark themes. Server state is TanStack Query; forms are react-hook-form + zod; UI is Tailwind CSS v3 with
CSS-variable design tokens plus [Magic UI](https://v3.magicui.design) components.

## Setup

```bash
cd frontend
cp .env.example .env        # VITE_API_BASE_URL=http://localhost:8000/api/v1
npm install
npm run dev                 # http://localhost:5173 (backend must be running on :8000)
```

The backend's default `CORS_ORIGINS=http://localhost:5173` already allows the dev server.

| Script | What it does |
|---|---|
| `npm run dev` | Vite dev server |
| `npm run build` | Typecheck (`tsc -b`) and production build to `dist/` |
| `npm test` | Vitest + React Testing Library (API mocked with MSW) |
| `npm run lint` / `npm run format` | ESLint / Prettier |
| `npm run gen:api` | Regenerate `src/api/schema.d.ts` from the running backend's `/openapi.json` |
| `npm run gen:api:file` | Regenerate from the committed `openapi.json` |
| `npm run magicui:add -- <name>` | Add a Magic UI component from the v3 registry |

### Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `VITE_API_BASE_URL` | `http://localhost:8000/api/v1` | API base URL, including `/api/v1`. Build-time (baked into the bundle). |

## API types (schema-first)

`src/api/schema.d.ts` is generated by `openapi-typescript` from the FastAPI OpenAPI schema. Never edit it.
`src/api/client.ts` is a small typed `fetch` wrapper: paths, path/query params, request bodies and responses
are all checked against the schema:

```ts
const page = await api.get("/clients", { query: { status: "live" } }); // Page_ClientOut_
await api.post("/clients/{client_id}/knowledge/approve", { path: { client_id }, body: { approved_by_name } });
```

It adds the bearer token, turns `{"error": {"code","message"}}` into an `ApiError`, and signs the user out on
401. After changing the backend:

```bash
npm run gen:api                                   # backend running on :8000
OPENAPI_URL=https://api.example.com/openapi.json npm run gen:api
```

Then run `npm run build` – type errors show exactly which screens need updating. Query hooks live in
`src/api/use*.ts`; query keys in `src/api/keys.ts`.

## Magic UI

Components come from the **Tailwind v3 registry** (`https://v3.magicui.design/r/<name>.json`) and are vendored
into `src/components/magicui/` by `scripts/add-magicui.mjs` (list in `scripts/magicui.json`). Their keyframes
are merged into `tailwind.config.ts` via `tailwind-extend.json`. shadcn-style colour names they use
(`background`, `border`, `primary`, …) map onto our tokens in `src/index.css`.

|---|---|
| NumberTicker | Stat tiles, pipeline counts, report numbers (Indian digit grouping) |
| MagicCard | Dashboard stat tiles (spotlight hover) |
| AnimatedCircularProgressBar | Paying clients toward the goal of 10 |
| AnimatedList | "Needs attention" list |
| BlurFade | Section entrances (dashboard, report) |

Marketing-only pieces (globe, device mockups, marquees, tweet cards) were left out of this admin tool. All
motion respects the OS "reduce motion" setting (`MotionConfig reducedMotion="user"` plus static fallbacks).

## Deployment

Add a `web` service next to `db` and `api` in your `docker-compose.yml` (paths assume the compose file sits
beside the `backend/` and `frontend/` folders):

```yaml
  web:
    build:
      context: ./frontend
      args:
        VITE_API_BASE_URL: /api/v1
    depends_on: [api]
    ports: ["5173:80"]
    restart: unless-stopped
```

`docker compose up --build` then builds this app into an Nginx image and serves it at
**http://localhost:5173** (port 80 in the container). Nginx proxies `/api/` to the `api` service, so the image
is built with `VITE_API_BASE_URL=/api/v1` and no CORS setup is needed.

For another host, build with the public API URL, or keep the same-origin proxy:

```bash
docker build --build-arg VITE_API_BASE_URL=https://api.example.com/api/v1 -t botdesk-web ./frontend
```

If the UI and API are on different origins, add the UI origin to the backend's `CORS_ORIGINS`.

## Structure

```
src/
  api/          client.ts (typed fetch), schema.d.ts (generated), types.ts, keys.ts, use*.ts hooks
  components/   Button, Pill, Drawer, Dialog, Tabs, StatTile, DataTable, States, ChatBubble, ChatThread,

                reports, settings
  lib/          format.ts (INR, IST dates), phone.ts, clipboard.ts, theme.ts, storage.ts
  routes.tsx, main.tsx, index.css (tokens + Tailwind layers)
```
